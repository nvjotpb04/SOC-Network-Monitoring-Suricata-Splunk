# HTTP Activity Investigation – Suspicious Web Traffic

## 1. Investigation Overview

This lab investigation demonstrates how a SOC analyst can investigate
HTTP-related security alerts generated by Suricata and analyzed through
Splunk Enterprise.

The investigation focuses on HTTP methods, source and destination
systems, alert signatures, and event frequency.

The scenario is performed in an isolated security laboratory for
defensive cybersecurity training.

## 2. Detection Source

**Detection Source:** Suricata IDS  
**SIEM:** Splunk Enterprise  
**Event Type:** `alert`  
**Index:** `suricata`

## 3. Initial Detection

The analyst can begin by reviewing HTTP-related alerts and identifying
the HTTP methods observed in the network traffic.

```spl
index=suricata event_type=alert
| stats count by http.http_method
| sort - count
4. Investigation Steps
Step 1 – Analyze HTTP Methods
index=suricata event_type=alert
| stats count by http.http_method
| sort - count

The analyst reviews the HTTP methods and identifies unusual or unexpected
patterns.

Common methods may include:

GET
POST
HEAD
PUT
DELETE
OPTIONS

The presence of a particular HTTP method alone does not prove malicious
activity.

Step 2 – Analyze Source IP Addresses
index=suricata event_type=alert
| stats count by src_ip
| sort - count
| head 10

This helps identify systems generating a high number of alerts.

Step 3 – Analyze Destination IP Addresses
index=suricata event_type=alert
| stats count by dest_ip
| sort - count
| head 10

The analyst can determine which destination systems are receiving the
security events.

Step 4 – Review HTTP Activity Over Time
index=suricata event_type=alert
| timechart count

A sudden increase in alerts may require additional investigation.

Step 5 – Review Alert Signatures
index=suricata event_type=alert
| stats count by alert.signature
| sort - count

The analyst reviews the Suricata signatures associated with the HTTP
events.

5. Investigation Indicators
Indicator	Investigation Question
HTTP Method	Is the method expected for the application?
Source IP	Which system generated the request?
Destination IP	Which system received the traffic?
Alert Signature	What did Suricata detect?
Alert Frequency	Is the activity repeated?
Timestamp	When did the activity occur?
6. Analyst Assessment

HTTP activity should be evaluated in context.

The analyst should consider:

Whether the source system is authorized
Whether the destination hosts a web service
Whether the HTTP method is expected
Whether the activity is repeated
Whether Suricata generated additional related alerts
Whether other security logs support the finding

An unusual HTTP method or request does not automatically indicate an
attack.

7. Recommended Response

If the activity is determined to be suspicious, the SOC analyst may:

Continue monitoring the source.
Search for related Suricata alerts.
Correlate the activity with firewall or web-server logs.
Escalate the event according to SOC procedures.
Apply containment controls when authorized.
Document the investigation and supporting evidence.
8. Investigation Outcome

Status: Lab investigation

Potential Finding: Suspicious or unusual HTTP activity requiring
additional analysis.

Confidence: Requires supporting evidence.

The investigation demonstrates how a SOC analyst can use Suricata and
Splunk to analyze HTTP-related security events and perform structured
alert triage.
